# Workflow 并发预算计数修复

## 问题与约束

Phase 6 真实工具节点接线测试发现：SQLite 下两个节点同时预留工具预算时，
原实现先读计数再按旧值 CAS，但忽略零行更新，导致两次执行都被允许、计数只增一。
该问题不能通过提高预算、改测试预期或串行化所有工具掩盖。

预算准入必须在数据库内原子增加，同时校验非终态和模型/工具上限。
未成功更新恰好一行必须拒绝准入，不能继续调用模型或工具。
不改变普通/Deep 配额，不绕过执行计划预算、Scope 或 Command Bus。

## 证据

- 新实库并发回归用 Barrier 固定两个连接都读取旧计数的顺序。
- 修复前：容量1仍有2次准入；容量2只有1次持久计数，两项均失败。
- 修复后：容量1恰好准入1次，容量2准入2次，准入数与持久计数相同。
- 预算并发、Workflow Repository、实验引擎真实工具节点17项通过（12.47秒）；Ruff通过。
- 工具测试使用脚本 Provider 和无外部副作用的搜索执行器；没有真实模型/网络调用。
- SQL使用条件原子增量；PostgreSQL实际多连接执行仍待其环境门禁，不以SQLite结果替代。
